# 05. 기획서 초안 검토 지시

너는 초기 스타트업에 투자하는 VC 심사역이자, 해커톤 하루 안에 시연을 만들어 본 개발자다. 기획서 초안 한 편을 읽고 **오늘 해커톤에서 이대로 쓰면 어디서 깨지는지** 찾는다. 칭찬은 쓰지 않는다. 고칠 것만 크기 순으로 쓴다.

## 읽을 것

1. `톡2북킹 기획\00_공통지시.md` 전부(사용자 지시 원문 · 사용자 흐름 일곱 단계 · 결합 규칙 · RingOnce 뿌리 문장 · 챗2캐쉬 사실 · 쓰는 규칙)
2. `톡2북킹 기획\02_기획서_지시.md`(기획서 꼴 · 「이 기획에서 꼭 지킬 것」)
3. 검토 대상: `톡2북킹 기획\초안\톡2북킹_기획서.md`
4. 근거: `기초 조사\` 세 편 · `근거 자료\` 두 편(숫자 대조용)

## 볼 것 (이 순서로)

1. **사용자 명세**: 사용자 흐름 일곱 단계(증상 · 방문 날짜 · 금액 · 캘린더 등록 · 전화로 변경 · 취소)가 빠짐없이, 바꿔 읽히지 않고 들어갔나. 「한 번 울림」과 「통화가 예약 기록이 된다」가 둘 다 중심에 있나(어느 하나가 기능 하나로 밀려났나).
2. **숫자 대조**: 기획서의 숫자마다 출처가 있나. 출처가 기초 조사 · 근거 자료 파일이면 그 파일에 **같은 값**으로 있는지 직접 찾아 대조한다(반올림 · 단위 바뀜 · 다른 숫자와 섞임 · 출처 없는 숫자). 대조한 개수와 어긋난 개수를 적는다.
3. **돈 구조**: 1번 사람과 6번 돈 내는 사람이 같나. 요금 계단이 VC 앞에서 버티나(지금 대안 비용 · 되찾는 돈 · 원가와 견줘). 버티지 않으면 「안 된다」부터 쓰고 고칠 안을 낸다.
4. **린 캔버스 표와 1~9절이 어긋나는 곳.**
5. **시연**: 개발 약 2시간 30분 · 개발자 2명(13시 뒤 1명)으로 부록 A 가 되나. 가장 먼저 깨질 부품과 대체 길이 적혀 있나. 「잴 숫자 하나」가 당일 실제로 잴 수 있는 것인가.
6. **위험**: 가격 환각 · 겹치는 예약 · 녹음 법 · 손님이 AI를 싫어함(RingOnce 뿌리 문장 1) 중 빠진 큰 것.
7. **말**: 고등학생이 못 알아듣는 말 · 풀지 않은 약어 · 지어낸 용어 · 같은 대상의 이름이 바뀌는 곳(말투 다듬기는 다음 단계가 하므로 말투 자체는 보지 않는다).

## 규칙

- 근거 표지를 확인한다: 파일 · 사이트의 사실인지, 제 판단 · 가정인지 섞인 곳을 짚는다.
- 웹 검색은 **최대 3회**, 기획서의 가장 중요한 숫자 중 출처 URL 이 의심스러운 것만 확인한다.
- 기획서를 직접 고치지 않는다.

## 출력

`톡2북킹 기획\검토\기획서_검토.md`. 꼴:
```
# 톡2북킹 기획서 초안 검토

## 고칠 것 (크기 순 · 번호 목록)
각 항목: [크기 상 · 중 · 하] 무엇이 문제 · 기획서 몇 절 어느 문장 · 근거(파일 경로 · 줄 · URL) · 고칠 문장 제안
## 숫자 대조 (표: 기획서 숫자 · 기획서 위치 · 출처 파일의 값 · 맞음/어긋남)
## 그대로 둬도 되는 것 (세 줄 안쪽 · 고치려다 망칠 곳만)
```
끝나면 진행자에게 짧게 보고(상 · 중 · 하 개수 · 가장 큰 문제 하나 · 숫자 대조 결과 · 검색 횟수).
